1. ภาพรวม

Investhesis เป็นเว็บแอปส่วนตัว ผู้ใช้หนึ่งคนบันทึกหุ้นสหรัฐฯ และไทย (SET/mai) จัดกลุ่มเป็นลิสต์ และ import จากไฟล์ CSV หรือ Excel ระบบแบ่งเป็นสี่ส่วนที่ติดต่อกันตามเส้นทางด้านล่าง

เปิดเต็มหน้า: system-architecture.html (กด PATH, MAP หรือ LENS ในแผนภาพเพื่อไล่เส้นทาง)

  • Web (apps/web): React + Vite แบบ SPA คุยกับ API และ Supabase Auth เท่านั้น ไม่เข้าฐานข้อมูลเอง
  • API (apps/api): Fastify 5 เป็นตัวเดียวที่แตะฐานข้อมูล
  • Supabase: Postgres (schema app) และ Auth (email + password, invite-only)
  • Domain (packages/domain): คำศัพท์ กฎ และ Zod schema ที่ web กับ API ใช้ร่วมกัน เพื่อให้กรอกมือกับ import ตรวจด้วยกฎเดียวกัน

2. ชั้นของระบบ

ส่วนเทคโนโลยีหน้าที่ไม่ทำ
apps/webReact 19, Vite 8, TypeScript, Tailwind v4, shadcn/ui, React Router (data mode)UI, อ่านและเขียนผ่าน loader/action, เก็บ session ของ Supabaseไม่เข้า Postgres, ไม่เก็บ cache ข้าม route
apps/apiNode 24, Fastify 5, Zod 4, Drizzle บน pg, pino, joseตรวจ token, กฎธุรกิจ, query ที่กรองด้วย userId, สร้าง OpenAPIไม่จัดการบัญชีผู้ใช้, ไม่เปลี่ยน schema
packages/domainTypeScript + Zod เท่านั้นvocabulary ของ lens, กฎ market/exchange, ticker, default ของ economic cycle, canonicaliseRowไม่มี I/O
supabase/Supabase CLI, Postgres 17เป็นเจ้าของ DDL ทั้งหมด (migrations/*.sql), config ของ Auth, email templateไม่มี business logic ใน trigger

กฎของโปรเจกต์: ตารางทุกตัวอยู่ใน schema app และ API ต่อฐานข้อมูลแบบ direct หรือ session pooler เท่านั้น (transaction pooler ทำให้ prepared statement พัง)

3. API: pipeline, module และ route

pipeline ของทุก request

  1. request-id: ใส่ id ให้ทุก request และแนบใน error body
  2. security: helmet, CORS และ cache-control: no-store ทุก response
  3. authenticate: สร้าง req.identity ทุก path ยกเว้น path สาธารณะ (/health, /ready, /openapi.json) ผ่าน IdentityResolver ที่เลือกตาม AUTH_MODE
  4. route → service → repository: route ตรวจ input ด้วย Zod, service ใช้กฎธุรกิจ, repository รับ userId ทุกฟังก์ชัน
  5. error-handler: แปลงทุก error เป็น RFC 7807 application/problem+json ที่มี code และ requestId ไม่เปิดเผยชื่อ constraint หรือ SQL

module และ route

modulerouteหมายเหตุ
stocksGET/POST /stocks, GET/PATCH/DELETE /stocks/{id}ซ้ำ (market, ticker) ตอบ 409 stock_exists พร้อม existingStockId; lens_sources จำว่าค่าไหนตั้งเองหรือเป็นค่า default
listsGET/POST /lists, GET/PATCH/DELETE /lists/{id}, POST /lists/{id}/stocks, DELETE /lists/{id}/stocks/{stockId}ชื่อซ้ำ (ไม่สนตัวพิมพ์) ตอบ 409 list_name_taken; เพิ่มซ้ำตอบ 409 already_in_list
importsGET /imports/template.csv|.xlsx, POST /imports/preview, POST /importsmultipart ไม่เกิน 1 MB, 1,000 แถว; อ่าน CSV ด้วย csv-parse และ XLSX ด้วย exceljs
meGET /meตอบตัวตนที่ authenticate ได้
opsGET /health, GET /ready, GET /openapi.json/ready ตอบ 503 ถ้าต่อ DB ไม่ได้หรือกำลังปิดตัว

ไฟล์ OpenAPI ที่ /openapi.json สร้างจาก Zod schema ของ route ทุก route ที่ไม่ใช่สาธารณะประกาศ bearerAuth

4. Web: route, data และ auth

  • Routes: /stocks, /stocks/new, /stocks/:id, /stocks/:id/edit, /lists, /lists/:id, /import-export และ /auth/* ทุกหน้าโหลดแบบ lazy จึงแยก chunk
  • Data: แต่ละ view มี loader (และ action ถ้าเขียนข้อมูล) เรียกผ่าน lib/api-client.ts หลัง action React Router โหลด loader ใหม่ให้เอง จึงไม่ต้องมี client cache (ADR-008)
  • api-client: ใส่ /api prefix และ bearer token, แปลง problem+json เป็น ApiError (status, code, errors, existingStockId), ได้ 401 แล้ว refresh ครั้งเดียวและลองใหม่ ถ้ายังไม่ผ่านจะ sign out
  • Auth guard: middleware ของ route app ตรวจ session ก่อน loader ใดทำงาน จึงไม่ต้องตรวจซ้ำใน loader
  • Import wizard: เก็บ File ใน state ข้ามขั้น เพราะ confirm ต้องส่งไฟล์เดิมอีกครั้ง; error CSV สร้างในเบราว์เซอร์

5. Data model

ทุกตารางอยู่ใน schema app id เป็น UUIDv7 ที่ API สร้าง ค่า lens เก็บเป็น text และตรวจด้วย @investhesis/domain ส่วน CHECK ใช้เฉพาะ market, exchange, currency, ticker และ name

app.stocks

  • id uuid PK
  • user_id uuid
  • market US | TH
  • ticker, exchange, currency, name
  • index_membership text[]
  • gics_sector, set_industry_group
  • value_chain, value_chain_position
  • size, style, economic_cycle
  • lynch_type, life_cycle, moat, volatility
  • customers, revenue_types, themes text[]
  • lens_sources jsonb
  • created_at, updated_at

app.lists

  • id uuid PK
  • user_id uuid
  • name 1–60 ตัวอักษร
  • created_at, updated_at

app.list_stocks

  • list_id, stock_id PK ร่วม
  • user_id uuid
  • added_at
  • FK (list_id, user_id) → lists, cascade
  • FK (stock_id, user_id) → stocks, cascade

ความสัมพันธ์: หนึ่งหุ้นอยู่ได้หลายลิสต์ และหนึ่งลิสต์มีได้หลายหุ้น ผ่านตาราง list_stocks การลบหุ้นหรือลิสต์ลบเฉพาะแถวสมาชิก ไม่ลบอีกฝั่ง

constraintกฎ
stocks_exchange_marketUS ใช้ NYSE หรือ NASDAQ และสกุล USD; TH ใช้ SET หรือ mai และสกุล THB
stocks_user_market_tickerผู้ใช้หนึ่งคนมี (market, ticker) ซ้ำไม่ได้ แต่คนละผู้ใช้หรือคนละ market ใช้ ticker เดียวกันได้
stocks_id_user, lists_id_userunique คู่ (id, user_id) เพื่อเป็นเป้าของ foreign key แบบ composite
lists_user_name_ciชื่อลิสต์ซ้ำกันไม่ได้ในผู้ใช้เดียว โดยไม่สนตัวพิมพ์เล็กใหญ่
ticker patternตัวพิมพ์ใหญ่ ตัวเลข จุด และขีด ยาว 1–12 ตัว ขึ้นต้นด้วยตัวอักษรหรือตัวเลข

Drizzle ใน apps/api/src/db/schema/ เขียนมือไว้สำหรับ query เท่านั้น มี drift test เทียบกับ information_schema ของฐานข้อมูลที่ migrate แล้ว (ไม่ใช้ drizzle-kit)

6. การแยกข้อมูลรายผู้ใช้

ข้อมูลของผู้ใช้แต่ละคนถูกกันด้วยสามชั้น เพื่อไม่ให้พึ่งชั้นเดียว

  1. Repository: ทุกฟังก์ชันรับ userId และกรองด้วยค่านี้ id ของผู้ใช้อื่นจึงตอบ 404 not_found เหมือนไม่มีอยู่ (ADR-003)
  2. Composite foreign key: list_stocks อ้างอิง (id, user_id) ทำให้ผูกลิสต์ของคนหนึ่งกับหุ้นของอีกคนไม่ได้ แม้โค้ดผิดก็ถูก DB ปฏิเสธ (SQLSTATE 23503)
  3. ปิดทาง Data API: ถอนสิทธิ์ schema app จาก anon และ authenticated และเปิด RLS โดยไม่มี policy ต่อให้คีย์รั่ว REST ของ Supabase ก็เข้าตารางไม่ได้ (ADR-002)

มี test สองผู้ใช้พิสูจน์ว่าผู้ใช้ V ได้ 404 ทุก route ของข้อมูลผู้ใช้ U และเพิ่มหุ้นของ U ลงลิสต์ของ V ไม่ได้

7. Auth: token และ sign-up

เปิดเต็มหน้า: auth-sign-in-sequence.html

  • ตรวจ token ในเครื่อง: API ใช้ jose ตรวจลายเซ็นด้วย JWKS ที่ cache ไว้ รับเฉพาะ ES256 และ RS256 แล้วตรวจ issuer, audience, exp และ sub (ต้องเป็น UUID, role=authenticated, ไม่ใช่ anonymous) ไม่ต้องเรียก Supabase ทุก request และไม่มี shared secret ใน API (ADR-001)
  • ทุกความล้มเหลวเป็น 401 unauthenticated พร้อม WWW-Authenticate: Bearer โดยเหตุผลอยู่ใน log เท่านั้น
  • JWKS ล่ม: ตอบ 503 auth_unavailable พร้อม Retry-After ไม่ใช่ 401 เพื่อไม่ให้ web sign out ผู้ใช้เพราะ Supabase สะดุด (ADR-007)
  • ลิงก์ในอีเมล ใช้ token_hash กับ verifyOtp ใน loader ของ /auth/confirm เปิดข้ามเบราว์เซอร์ได้ และไม่มี token ค้างใน URL (ADR-002)
  • Session อยู่ใน localStorage ผ่าน supabase-js (ADR-003) และมีเพียง supabase-auth-client.ts ที่ import SDK เพราะ web ใช้รูปแบบ AuthClient port กับ adapter (ADR-005)
  • Sign-up แบบ invite-only: hook Before User Created ตรวจ app.signup_allowlist (อีเมลเดี่ยวหรือทั้งโดเมน) ก่อนสร้างผู้ใช้และก่อนส่งอีเมลใด ๆ (ADR-009)
  • โหมด mock: AUTH_MODE=mock ทำให้ทุก request เป็นผู้ใช้คนเดียวสำหรับ dev และ test config จะปฏิเสธเมื่อ NODE_ENV=production

8. Import

เปิดเต็มหน้า: import-flow-sequence.html

  • ไม่เก็บสถานะ (ADR-006): preview อ่านและตรวจโดยไม่เขียนอะไรเลย ส่วน confirm อ่านไฟล์เดิมใหม่แล้วเขียนทั้งหมดใน transaction เดียว ไม่มีตาราง session ไม่มีงานลบหมดอายุ และไม่เก็บไฟล์ ราคาที่จ่ายคืออัปโหลดสองครั้ง (≤ 1 MB)
  • ตรวจซ้ำตอน confirm: หุ้นที่ผู้ใช้เพิ่มระหว่าง preview กับ confirm จะกลายเป็น duplicate ไม่ใช่ error
  • ทั้งหมดหรือไม่เลย: ถ้าล้มกลางทาง rollback ทั้งก้อน (stocks, lists และ memberships ไม่เปลี่ยน)
  • โหมด duplicate: skip ข้ามแต่ยังเพิ่มเข้าลิสต์ หรือ update เขียนทับเฉพาะเซลล์ที่ไม่ว่างและทำเครื่องหมายเป็นค่าที่ตั้งเอง
  • ไฟล์: อ่านที่ API (csv-parse รองรับ BOM, exceljs อ่านชีตแรกและผลของสูตรที่ cache ไว้) เพื่อให้ตัวตรวจเดียวกับการกรอกมือ และ template สร้างจาก TEMPLATE_COLUMNS จึงไม่เคยเพี้ยนจากตัวอ่าน (ADR-007, ADR-010)
  • ข้อจำกัด: ไฟล์ ≤ 1 MB, ≤ 1,000 แถว, UTF-8; error ระดับไฟล์ใช้ code file_too_large, file_unsupported, file_too_many_rows, file_empty, file_missing_headers

9. การตัดสินใจสำคัญ (ADR)

เรื่องเลือกเหตุผล
MigrationSupabase CLI, SQL ใน supabase/migrations/เป็น SQL ธรรมดา ใช้ db reset ในเครื่องและ db push บน hosted; Drizzle ใช้ query อย่างเดียว
ที่อยู่ของตารางschema app ที่ไม่เปิด Data APIกัน REST อัตโนมัติของ Supabase ไม่ให้เข้าถึงข้อมูล
แยกข้อมูลรายผู้ใช้userId ใน repository + composite FKเข้ากับ DB role เดียวของ API และกัน join ข้ามผู้ใช้ที่ระดับ DB
ค่า lens ใน DBtext ตรวจด้วย domain packagevocabulary เปลี่ยนบ่อย; เปลี่ยน enum หรือ CHECK ต้อง migration ทุกครั้ง
แชร์กฎระหว่าง web และ APIpackages/domain ส่งออก source TypeScript (erasable syntax)Vite compile ให้ web และ Node 24 ลบ type ตอนรัน จึงไม่ต้อง build ระหว่างพัฒนา (พิสูจน์แล้วใน T-002)
สถานะของ importstateless: preview และ confirm ส่งไฟล์ทั้งคู่ไม่มีตารางหรืองานหมดอายุ และ confirm ตรวจกับ DB ตอนเขียน
Server state ใน webloader/action ของ React Routerrouter อยู่ใน data mode แล้ว revalidation หลัง action พอสำหรับงานนี้ ไม่ต้องเพิ่ม dependency
ติดตามค่าอัตโนมัติกับค่าที่ตั้งเองlens_sources jsonbไม่ต้องเพิ่ม 14 คอลัมน์ และต่อยอดค่า stale ได้โดยไม่ migrate แถว
การตรวจ tokenJWKS ในเครื่อง ด้วย joseไม่เรียกเครือข่ายทุก request, ไม่มี shared secret, หมุนคีย์ได้โดยไม่ต้อง deploy ใหม่
ลิงก์อีเมลtoken_hash + verifyOtpใช้ได้ข้ามเบราว์เซอร์ และไม่มี token ใน URL
ตารางผู้ใช้ไม่มี; user_id คือ id ของ Supabasev1 ยังไม่ต้องใช้ข้อมูลโปรไฟล์ และไม่ผูก migration กับ schema ภายในของ Supabase

รายละเอียดเต็มของแต่ละ ADR อยู่ที่ docs/features/stock-lists/v1.0/design.md และ docs/features/user-auth/v1.0/design.md

11. ความเสี่ยงและเรื่องที่ยังเปิดอยู่

  • XLSX ขยายตัวในหน่วยความจำ: ไฟล์ที่บีบอัดอาจขยายมากตอนโหลด ถูกจำกัดด้วย 1 MB และ 1,000 แถวเท่านั้น (ตรวจจำนวนแถวหลังโหลด) ยอมรับได้สำหรับผู้ใช้เดียวใน v1
  • Token ใน localStorage: XSS ทำให้อันตรายขึ้น ควรเพิ่ม CSP เมื่อเลือกที่ host
  • Config ของ hosted กับ local อาจไม่ตรงกัน: เช็กลิสต์ hosted ทำมือ และ E2E ครอบคลุมเฉพาะ local
  • Type stripping ของ workspace package: ถ้า Node หรือ tsc รุ่นใหม่ทำให้พัง จะเห็นจาก pnpm build และ test ของ API
  • Contrast ของข้อความ destructive: ปุ่มยืนยันลบในโหมดสว่างยังตกเกณฑ์ (F-2 ถึง F-4 ใน test report) รอตัดสินใจเรื่อง theme token
  • Test หน่วงเวลา TC-C-114 (render 200 หุ้นภายใน 200 ms) เคยล้มครั้งเดียวตอนเครื่องโหลดหนัก
  • ยังไม่เลือก: ผู้ให้บริการ SMTP สำหรับ production (OQ-1) และที่ deploy ของ API กับ web
  • นอก scope ของ v0.2.0: ราคา/กราฟสด, ข้อมูลตลาดและ market cap อัตโนมัติ, concentration, thesis notes, i18n ไทย/อังกฤษ และ export เต็มรูปแบบ
เอกสารนี้สรุปจาก design.md ของ stock-lists และ user-auth กับโค้ดที่ commit ใน v0.2.0 ถ้าโค้ดเปลี่ยน ให้แก้ที่นี่และอัปเดต diagram ใน source/ ด้วย
