Architecture และ System Design

เอกสารสถาปัตยกรรมของ Investhesis ตามระบบที่สร้างไว้ใน v0.2.0 (user-auth และ stock-lists) ประกอบด้วยบทอธิบายหนึ่งหน้าและแผนภาพแบบโต้ตอบสามชุด

System Design

ชั้นของระบบ API pipeline data model การแยกข้อมูลรายผู้ใช้ ADR การทดสอบ และความเสี่ยง

แผนภาพสถาปัตยกรรม

web, API, Supabase Auth, Postgres และ domain package เชื่อมกันอย่างไร

ลำดับ Sign-in

sign-in, เรียก API ด้วย Bearer token และการ refresh เมื่อ token หมดอายุ

ลำดับ Import

preview ที่ไม่เขียนอะไร แล้ว confirm ใน transaction เดียว

สรุปใน 5 ข้อ

  1. API เป็นทางเดียวสู่ฐานข้อมูล เบราว์เซอร์คุยกับ API และ Supabase Auth เท่านั้น
  2. ข้อมูลแยกรายผู้ใช้สามชั้น: repository กรองด้วย userId, foreign key แบบ (id, user_id) และปิดทาง Data API ของ Supabase
  3. ตรวจ token ในเครื่อง ด้วย JWKS ที่ cache ไว้ ไม่เรียก Supabase ทุก request
  4. กฎชุดเดียว ใน packages/domain ใช้ทั้งตอนกรอกมือและตอน import
  5. Import ไม่เก็บสถานะ: preview ไม่เขียนอะไร confirm เขียนทั้งหมดใน transaction เดียว

วิธีใช้แผนภาพ

  • แต่ละแผนภาพเป็นไฟล์ HTML ไฟล์เดียว เปิดได้ด้วยการดับเบิลคลิก ไม่ต้องมี server
  • ปุ่มมุมขวาบนสลับโหมดสว่างและมืด เปลี่ยนสไตล์ เปิดโหมดนำเสนอ และ Export เป็นภาพได้
  • กด PATH, MAP หรือ LENS ที่มุมขวาล่างเพื่อไล่เส้นทางความสัมพันธ์ ค้นหา หรือโฟกัสบาง node
  • ข้อความในแผนภาพเป็นภาษาไทย ส่วนปุ่มและเมนูของตัวแสดงผลเป็นภาษาอังกฤษ
