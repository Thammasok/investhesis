Setup โปรเจกต์ Supabase (local) Supabase (hosted) แก้ปัญหา

แก้ปัญหาที่เจอบ่อย

อาการ สาเหตุ และวิธีแก้ เรียงตามที่เจอบ่อยตอน setup

pnpm test ล้มเหลว หรือ API ตอบ 503 db_unavailable

สาเหตุ: test ของ API แตะฐานข้อมูลจริง ถ้า Supabase local ไม่ได้รันอยู่ จะต่อ DB ไม่ได้

docker info          # Docker ต้องเปิดอยู่
pnpm db:start        # เปิด stack
pnpm db:reset        # ให้ schema ตรงกับ migration ล่าสุด
curl -s http://localhost:3000/ready
pnpm test:e2e ขึ้น "http://localhost:5173/auth/sign-in is already used"

สาเหตุ: มีโปรแกรมอื่น (เช่น dev server ของโปรเจกต์อื่น) ใช้พอร์ต 5173 อยู่

แก้: อย่าปิดโปรแกรมนั้น ให้ย้าย E2E ไปพอร์ตอื่น

E2E_WEB_PORT=5174 pnpm test:e2e

ดูว่าใครใช้พอร์ต: lsof -nP -iTCP:5173 -sTCP:LISTEN

E2E ล้มเหลวเพราะไม่มี browser 
pnpm exec playwright install chromium
sign-up ถูกปฏิเสธ: "Sign-up is invite-only. Ask the owner to add this email."

สาเหตุ: อีเมลไม่ตรงกับแถวใน app.signup_allowlist (error signup_not_allowed)

  • บนเครื่อง ใช้อีเมลลงท้าย @example.test หรือเพิ่มแถวเอง (ดู Allowlist)
  • แถว @example.com ไม่ครอบคลุม @mail.example.com ต้องเพิ่มแยก
  • หลัง pnpm db:reset แถวที่เพิ่มเองหายไป เหลือแค่จาก seed
ไม่เห็นอีเมลยืนยัน
  • อีเมลทั้งหมดบนเครื่องไปที่ Mailpit: http://127.0.0.1:54324 ไม่ส่งออกอินเทอร์เน็ต
  • Auth เว้น 60 วินาทีต่อการส่งอีเมลหนึ่งที่อยู่ ถ้ากดซ้ำเร็วเกินไปจะไม่ส่ง
  • ถ้าลิงก์ในอีเมลเปิดพอร์ตผิด เพราะ site_url คือ http://localhost:5173 เปลี่ยนพอร์ตในเบราว์เซอร์ หรือแก้ supabase/config.toml แล้ว pnpm db:stop && pnpm db:start
หน้าเว็บ error ทันทีตอนเปิด: "VITE_SUPABASE_URL is required…"

สาเหตุ: VITE_AUTH_MODE เป็น supabase (ค่าเริ่มต้นถ้าไม่ตั้ง) แต่ไม่มี URL หรือ publishable key ใน apps/web/.env

แก้: ตั้ง VITE_AUTH_MODE=mock เพื่อพัฒนาโดยไม่ต้อง sign-in หรือใส่ค่าให้ครบ (ดู ลอง sign-in จริง) แล้ว restart pnpm dev เพราะ Vite อ่าน .env ตอนเริ่ม

ทุก request จาก web ได้ 401
  • web เป็น mock แต่ API เป็น supabase: web ไม่ส่ง token ให้ตั้งสองฝั่งให้ตรงกัน
  • เปลี่ยน .env ของ API แล้ว ต้องรอ node --watch รีสตาร์ท หรือรัน pnpm dev:api ใหม่
แก้ hook ใน config.toml แล้วไม่มีผล

pnpm db:reset ไม่โหลด config ของ Auth ใหม่ ให้ restart ทั้ง stack

pnpm db:stop && pnpm db:start
พอร์ตของ Supabase ชน (54321–54324, 54329)

หยุด Supabase ตัวอื่นที่รันอยู่ก่อน (supabase stop ในโปรเจกต์นั้น) หรือเปลี่ยนพอร์ตใน supabase/config.toml แล้วอัปเดต DATABASE_URL และ SUPABASE_URL ให้ตรงกัน

prepared statement error หรือ query ค้างบน hosted

สาเหตุ: ใช้ transaction pooler (พอร์ต 6543) กับ DATABASE_URL

แก้: ใช้ direct connection หรือ session pooler (พอร์ต 5432) และต่อท้าย ?sslmode=require

Node ฟ้อง type หรือ syntax ที่ไม่รู้จักตอนรัน API

API รัน TypeScript ด้วย Node โดยตรง ต้องใช้ Node 24 ขึ้นไป และเขียนได้เฉพาะ syntax ที่ลบ type ออกแล้วรันได้ (ไม่ใช้ enum หรือ parameter properties) เช็กด้วย node -v

test ที่นับแถวในฐานข้อมูลล้มเหลวเป็นบางครั้ง

ไฟล์ test หลายไฟล์ใช้ฐานข้อมูลเดียวกันและรันขนานกัน ให้นับเฉพาะแถวของ user ที่ test สร้างเอง (where user_id = ...) อย่านับทั้งตาราง
