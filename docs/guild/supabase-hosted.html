Supabase แบบ hosted

เช็กลิสต์ตั้งค่าโปรเจกต์บน Supabase Cloud ให้ทำงานเหมือน local stack หน้านี้ครอบคลุมเฉพาะฝั่ง Supabase และ env ที่ต้องส่งให้ API กับ web ยังไม่ได้เลือกที่ deploy ตัว API และ web

ยังไม่มีการ push config อัตโนมัติ: จนกว่าจะรัน supabase config push ค่าใน dashboard คือแหล่งความจริงของโปรเจกต์ hosted ดังนั้นต้องตั้งค่าตามเช็กลิสต์ด้านล่างด้วยมือ

ในหน้านี้
  1. สร้างโปรเจกต์และ link
  2. ส่ง migration
  3. ตั้งค่า Auth
  4. เปิด hook และใส่ allowlist
  5. อีเมลสำหรับ production
  6. ค่า env ที่ API และ web ต้องใช้
  7. เช็กลิสต์รวม

1. สร้างโปรเจกต์และ link

  1. สร้างโปรเจกต์ใหม่ที่ supabase.com/dashboard จดรหัสผ่านฐานข้อมูลและ project ref
  2. Login และ link CLI กับโปรเจกต์ (ใช้ CLI ที่ติดมากับ repo) 
    pnpm exec supabase login
pnpm exec supabase link --project-ref <project-ref>

2. ส่ง migration

pnpm exec supabase db push

คำสั่งนี้รันไฟล์ใน supabase/migrations/ ทั้งหมดบนฐานข้อมูล hosted ได้แก่ schema app, app.signup_allowlist, app.hook_before_user_created และตารางของ stock lists

ไม่มี seed บน hosted: seed.sql ใช้เฉพาะ local ดังนั้นตาราง allowlist บน hosted เริ่มต้นว่าง ต้องเพิ่มอีเมลของเจ้าของเองก่อนสมัครครั้งแรก (หัวข้อ 4)

3. ตั้งค่า Auth

ทำใน dashboard หัวข้อ Authentication ให้ตรงกับ local

ที่ค่า
URL configurationSite URL คือ origin ของ web; Redirect URLs มี <origin>/**
Sign-in providers → Emailเปิด confirm email, ปิด secure password change, เปิด require current password
รหัสผ่านและการสมัครความยาวขั้นต่ำ 8; ปิด anonymous sign-ins; เปิด sign-ups
JWTexpiry 3600 วินาที; เปิด refresh token rotation, reuse interval 10 วินาที
JWT signing keysให้ใช้คีย์ ES256 เป็นคีย์ปัจจุบัน (rotate จาก legacy secret) เพื่อให้ JWKS endpoint เสิร์ฟคีย์นี้ API ตรวจ token ด้วย JWKS
Email templatesวางเนื้อหา supabase/templates/confirmation.html (Confirm signup) และ recovery.html (Reset password)

ตรวจว่า JWKS เสิร์ฟคีย์ ES256:

curl -s https://<project-ref>.supabase.co/auth/v1/.well-known/jwks.json

4. เปิด hook และใส่ allowlist

  1. Authentication → Hooks: เปิด Before User Created
    TypePostgres function
    Schemaapp
    Functionhook_before_user_created
  2. ใส่อีเมลของเจ้าของ ก่อน สมัครครั้งแรก (SQL editor ใน dashboard) 
    insert into app.signup_allowlist (pattern, note) values ('owner@example.com', 'owner');

    hook นี้กันผู้ใช้ที่สร้างผ่าน admin API ด้วย ไม่ใช่แค่หน้า sign-up

5. อีเมลสำหรับ production

mailer ที่ติดมากับ Supabase ใช้ทดสอบเท่านั้น สำหรับ production ให้ตั้ง custom SMTP ใน Auth ผู้ให้บริการที่ใช้ได้และมี free tier หรือราคาต่ำ:

  • Resend (มี free tier)
  • Brevo (มี free tier)
  • Amazon SES (ราคาต่ำ คิดตามจำนวนข้อความ)

ยังไม่ได้เลือกเจ้าไหน (requirements OQ-1 รอเจ้าของตัดสินใจก่อน deploy) หลังตั้ง SMTP แล้วให้ทบทวน email rate limit อีกรอบ

6. ค่า env ที่ API และ web ต้องใช้

API

ตัวแปรค่า
NODE_ENVproduction (โหมด mock ถูกปฏิเสธเมื่อเป็น production)
AUTH_MODEsupabase
SUPABASE_URLhttps://<project-ref>.supabase.co
DATABASE_URLจากหน้า Connection string ใน Project Settings → Database ใช้แบบ direct หรือ session pooler (พอร์ต 5432) ห้ามใช้ transaction pooler (6543) เพราะ prepared statement พัง และต่อท้ายด้วย ?sslmode=require
PUBLIC_WEB_ORIGIN, CORS_ORIGINSorigin ของ web ที่ deploy จริง
TRUST_PROXYตั้งเป็น true เมื่ออยู่หลัง reverse proxy

web (ตอน build)

ตัวแปรค่า
VITE_AUTH_MODEsupabase
VITE_SUPABASE_URLhttps://<project-ref>.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEYpublishable key ของโปรเจกต์ (ดูได้ใน dashboard ของโปรเจกต์) เป็นคีย์สาธารณะ ใส่ใน bundle ได้

ห้ามเอาไปใส่ใน web หรือ commit: secret key, service role key และรหัสผ่านฐานข้อมูล ใช้ได้เฉพาะฝั่งเซิร์ฟเวอร์

7. เช็กลิสต์รวม

  • URL configuration: Site URL เป็น origin ของ web; Redirect URLs มี <origin>/**
  • Email provider: เปิด confirm email, ปิด secure password change, เปิด require current password
  • ความยาวรหัสผ่านขั้นต่ำ 8; ปิด anonymous sign-ins; เปิด sign-ups
  • JWT expiry 3600 วินาที; refresh token rotation เปิด, reuse interval 10 วินาที
  • Email templates: วาง confirmation.html และ recovery.html
  • JWT signing keys: คีย์ ES256 เป็นคีย์ปัจจุบัน และ JWKS endpoint เสิร์ฟคีย์นั้น
  • ตั้ง custom SMTP แล้ว (OQ-1) และทบทวน email rate limit
  • supabase db push สำเร็จ (มี app.signup_allowlist และ app.hook_before_user_created)
  • เปิด hook Before User Created (Postgres function, schema app)
  • ใส่อีเมลเจ้าของลง allowlist ก่อนสมัครครั้งแรก
  • ตั้ง env ของ API (DATABASE_URL แบบ session/direct + sslmode=require) และของ web ตามหัวข้อ 6
  • ทดสอบ: สมัครด้วยอีเมลใน allowlist, ยืนยันอีเมล, เข้า /stocks ได้ และอีเมลนอก allowlist ถูกปฏิเสธ
