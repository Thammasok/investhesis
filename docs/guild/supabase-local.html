Supabase บนเครื่อง (local)

Supabase ของโปรเจกต์นี้ใช้สองอย่าง: Postgres ที่ API เข้าถึงผ่าน DATABASE_URL และ Auth (email + password) ที่ API ตรวจ token ผ่าน JWKS เบราว์เซอร์ไม่เรียก Postgres โดยตรง

ในหน้านี้
  1. เปิดและปิด stack
  2. บริการและพอร์ต
  3. Migration และ seed
  4. ลอง sign-in จริงบนเครื่อง
  5. Allowlist สำหรับ sign-up
  6. เปลี่ยน config ของ Auth
  7. ตรวจว่าตั้งค่าถูก

1. เปิดและปิด stack

pnpm db:start        # สร้าง signing key ถ้ายังไม่มี แล้ว supabase start
pnpm db:reset        # ล้างฐานข้อมูล แล้วรัน migration + seed.sql ใหม่
pnpm db:stop         # ปิด container
  • pnpm db:start เรียก pnpm db:keys ก่อน ซึ่งสร้าง supabase/signing_keys.json (คีย์ ES256 สำหรับเซ็น JWT) ถ้ามีแล้วจะไม่เขียนทับ ไฟล์นี้อยู่ใน .gitignore ห้าม commit
  • ต้องเปิด Docker ก่อน ครั้งแรกจะ pull image หลายตัว
  • db:reset ลบข้อมูลทั้งหมด ในฐานข้อมูล local รวมถึงผู้ใช้ที่สมัครไว้

ช่วงแรกหลัง start: Auth โหลด email template ใหม่ทุก ~10 วินาที และ Kong ขึ้นหลัง Auth ดังนั้นไม่กี่วินาทีแรก อีเมลอาจยังเป็นข้อความเดิมของ Supabase ชุด pnpm test:supabase จะรอ template ที่กำหนดเองก่อนทดสอบ

2. บริการและพอร์ต

บริการURLใช้ทำอะไร
API gatewayhttp://127.0.0.1:54321Auth อยู่ที่ /auth/v1 (ค่า SUPABASE_URL)
Postgrespostgresql://postgres:postgres@127.0.0.1:54322/postgresค่า DATABASE_URL ของ API
Studiohttp://127.0.0.1:54323หน้า dashboard และ SQL editor
Mailpithttp://127.0.0.1:54324อีเมลทุกฉบับที่ Auth ส่งจะมาลงที่นี่ ไม่ออกไปข้างนอก

พอร์ตอื่นที่ config ใช้: 54320 (shadow DB ของ CLI) และ 54329 (pooler) ถ้าพอร์ตชนกับโปรแกรมอื่น ดู แก้ปัญหา

ดูค่าทั้งหมดของ stack ที่รันอยู่:

pnpm exec supabase status -o env

3. Migration และ seed

Schema ทั้งหมดเป็น SQL ใน supabase/migrations/ เท่านั้น (ไม่ใช้ drizzle-kit) ส่วน Drizzle ใน apps/api/src/db/schema/ เขียนมือไว้สำหรับ query และมี drift test เทียบกับฐานข้อมูลจริง

ไฟล์ทำอะไร
20261121000000_signup_allowlist.sqlschema app, ตาราง app.signup_allowlist และฟังก์ชัน app.hook_before_user_created
20261121000100_stock_lists.sqlตาราง app.stocks, app.lists, app.list_stocks (เปิด RLS ไม่มี policy, ถอนสิทธิ์ของ anon และ authenticated)
seed.sqlใส่ @example.test ลง allowlist (ทุก test ใช้โดเมนนี้)

เพิ่ม migration ใหม่

pnpm exec supabase migration new add_something
# แก้ไฟล์ SQL ที่เพิ่งสร้างใน supabase/migrations/
pnpm db:reset            # ลองรันทั้งชุดตั้งแต่ศูนย์
pnpm test                # drift test จะฟ้องถ้า Drizzle ไม่ตรงกับ DB

กฎของโปรเจกต์: ตารางทุกตัวอยู่ใน schema app และไม่เขียน business logic ใน trigger ถ้าเพิ่มหรือเปลี่ยนคอลัมน์ ต้องแก้ Drizzle typings ให้ตรงด้วย

4. ลอง sign-in จริงบนเครื่อง

ค่าเริ่มต้นของ web คือ mock ถ้าอยากลอง sign-up และ sign-in ผ่าน Supabase Auth จริง ทำตามนี้

  1. เปิด stack และใส่ schema 
    pnpm db:start && pnpm db:reset
  2. เอา publishable key 
    pnpm exec supabase status -o env | grep -E 'PUBLISHABLE_KEY|ANON_KEY'

    คีย์นี้เป็นคีย์สาธารณะ ใส่ใน bundle ของ web ได้ ส่วน SECRET_KEY และ SERVICE_ROLE_KEY ห้ามเอาไปใส่ใน web

  3. ตั้ง apps/web/.env 
    VITE_AUTH_MODE=supabase
VITE_SUPABASE_URL=http://127.0.0.1:54321
VITE_SUPABASE_PUBLISHABLE_KEY=<ค่า PUBLISHABLE_KEY จากขั้นก่อน>
  4. ตั้ง apps/api/.env ให้เป็นโหมด supabase 
    AUTH_MODE=supabase
SUPABASE_URL=http://127.0.0.1:54321
  5. รัน pnpm dev แล้วสมัครสมาชิก ที่ http://localhost:5173/auth/sign-up ด้วยอีเมลลงท้าย @example.test (เช่น me@example.test) เพราะ allowlist ในเครื่องมีแค่โดเมนนี้ ดูวิธีเพิ่มอีเมลอื่นใน หัวข้อ 5
  6. เปิด Mailpit ที่ http://127.0.0.1:54324 หาอีเมลยืนยัน แล้วคลิกลิงก์ ลิงก์ชี้ไปที่ http://localhost:5173/auth/confirm?... เมื่อยืนยันแล้วจะเข้าระบบและไปหน้า /stocks

พอร์ต 5173 ถูกใช้อยู่? ลิงก์ในอีเมลชี้ไป site_url = http://localhost:5173 ถ้า web ของคุณรันพอร์ตอื่น ให้แก้ลิงก์ในเบราว์เซอร์เป็นพอร์ตที่ใช้จริง หรือเปลี่ยน site_url ใน supabase/config.toml (ต้อง db:stop แล้ว db:start)

หลังจากนั้นทุก request จาก web จะแนบ Authorization: Bearer <access token> API ตรวจ token (ES256, issuer, audience, exp, sub) และใช้ sub เป็น user id ที่กรองทุก query

5. Allowlist สำหรับ sign-up

ระบบเปิดสมัครแบบ invite-only: hook Before User Created ตอบ 403 signup_not_allowed ถ้าอีเมลไม่ตรงกับแถวใน app.signup_allowlist

  • หนึ่งแถวคืออีเมลหนึ่งอัน หรือทั้งโดเมน (ตัวพิมพ์เล็ก)
  • แถว @domain ไม่ครอบคลุม sub-domain ต้องเพิ่ม sub-domain เป็นแถวแยก
  • ตารางเข้าถึงได้เฉพาะ postgres และ supabase_auth_admin จึงต้องแก้ด้วย SQL
  • การลบแถวไม่ได้ลบบัญชีที่สมัครไปแล้ว

เปิด SQL editor ใน Studio (http://127.0.0.1:54323) หรือใช้ psql ที่พอร์ต 54322 แล้วรัน:

-- อนุญาตอีเมลเดียว
insert into app.signup_allowlist (pattern, note) values ('owner@example.com', 'owner');

-- อนุญาตทั้งโดเมน
insert into app.signup_allowlist (pattern, note) values ('@example.com', 'whole domain');

-- ลบออก
delete from app.signup_allowlist where pattern = 'owner@example.com';
psql postgresql://postgres:postgres@127.0.0.1:54322/postgres

pnpm db:reset จะล้างแถวที่คุณเพิ่มเอง เหลือแค่ @example.test จาก seed ถ้าอยากเก็บถาวรในเครื่อง ให้เพิ่มลง supabase/seed.sql

6. เปลี่ยน config ของ Auth

ค่าทั้งหมดอยู่ใน supabase/config.toml

หัวข้อค่า
Site URLhttp://localhost:5173
คีย์เซ็น JWTES256 จาก signing_keys.json
อายุ access token1 ชั่วโมง, มี refresh token rotation
รหัสผ่านยาวอย่างน้อย 8 ตัวอักษร
ยืนยันอีเมลบังคับ
เปลี่ยนรหัสผ่านต้องส่ง current_password (auth.email.require_current_password = true)
ส่งอีเมลซ้ำเว้น 60 วินาทีต่อที่อยู่
Email templatesupabase/templates/confirmation.html และ recovery.html ลิงก์ไปที่ {{ .SiteURL }}/auth/confirm?token_hash=...&type=email|recovery&next=...

แก้ hook ใน config.toml แล้วต้อง restart: pnpm db:stop && pnpm db:start เพราะ pnpm db:reset อย่างเดียวไม่โหลด config ของ Auth ใหม่

7. ตรวจว่าตั้งค่าถูก

# JWKS ต้องมี 1 คีย์: kty EC, crv P-256, alg ES256
curl -s http://127.0.0.1:54321/auth/v1/.well-known/jwks.json

# ตรวจ setting ของ Auth, allowlist และ flow ของ sign-up ที่ระดับ script
pnpm test:supabase

# ตรวจว่า API ต่อ DB ได้
curl -s http://localhost:3000/ready
