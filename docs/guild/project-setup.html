Setup โปรเจกต์

จากเครื่องใหม่ไปจนถึงรัน web และ API ได้ และรัน test ผ่าน

1. สิ่งที่ต้องมี

เครื่องมือเวอร์ชันใช้ทำอะไร
Node.js24 ขึ้นไปAPI รัน TypeScript ด้วย Node โดยตรง (type stripping) ไม่มีขั้น build ตอน dev
pnpm12.5.1 (ตาม packageManager)จัดการ workspace: apps/* และ packages/*
Dockerเวอร์ชันล่าสุด และต้องเปิดอยู่Supabase local stack รันเป็น container
Gitเวอร์ชันใดก็ได้โปรเจกต์ใช้ branch เดียวคือ main

Supabase CLI ไม่ต้องติดตั้งแยก เพราะเป็น devDependency ของ root (supabase) สคริปต์เรียกผ่าน pnpm exec supabase ให้เอง

node -v          # ต้องขึ้น v24.x ขึ้นไป
pnpm -v          # 12.5.1
docker info      # ต้องไม่ error

เปิด pnpm ด้วย corepack: ถ้ายังไม่มี pnpm ให้รัน corepack enable แล้ว corepack จะเลือกเวอร์ชันตาม packageManager ใน package.json ให้

2. ติดตั้ง dependencies

git clone <repo-url> investhesis
cd investhesis
pnpm install

คำสั่งเดียวติดตั้งให้ครบทุก package (web, api, domain) ถ้าจะรัน E2E ต้องติดตั้ง browser ของ Playwright ด้วย ทำครั้งเดียวต่อเครื่อง:

pnpm exec playwright install chromium

3. ตั้งค่า .env

ไฟล์ .env ถูก git ignore ไว้ ให้ copy จาก .env.example ของแต่ละ app

cp apps/api/.env.example apps/api/.env
cp apps/web/.env.example apps/web/.env

apps/api/.env

ตัวแปรค่า localหมายเหตุ
NODE_ENVdevelopmentบังคับต้องมี (development | test | production)
PORT3000web dev server proxy /api มาที่พอร์ตนี้
DATABASE_URLpostgres://postgres:postgres@127.0.0.1:54322/postgresใช้ direct หรือ session pooler เท่านั้น ห้ามใช้ transaction pooler (พอร์ต 6543)
AUTH_MODEsupabaseหรือ mock สำหรับ dev และ test (ถูกปฏิเสธเมื่อ NODE_ENV=production)
SUPABASE_URLhttp://127.0.0.1:54321ใช้ดึง JWKS มาตรวจ access token
PUBLIC_WEB_ORIGIN, CORS_ORIGINShttp://localhost:5173CORS_ORIGINS คั่นด้วย comma ได้

apps/web/.env

ตัวแปรค่าหมายเหตุ
VITE_AUTH_MODEmockค่าใน .env.example คือ mock (API รันเป็น mock user ไม่ต้อง sign-in)
VITE_SUPABASE_URLhttp://127.0.0.1:54321จำเป็นเมื่อใช้โหมด supabase
VITE_SUPABASE_PUBLISHABLE_KEY(ว่าง)จำเป็นเมื่อใช้โหมด supabase ดูวิธีเอาค่าใน Supabase (local)

ระวัง: ถ้า VITE_AUTH_MODE=supabase แล้วไม่ใส่ URL หรือ key แอปจะ throw error บอกชื่อตัวแปรที่ขาดทันทีตอนเริ่ม

4. รันระบบ

  1. เปิด Supabase local (Docker ต้องเปิดอยู่) 
    pnpm db:start

    ครั้งแรกจะ pull image หลายตัว ใช้เวลาหลายนาที คำสั่งนี้สร้าง supabase/signing_keys.json (git ignore) ให้เองถ้ายังไม่มี

  2. ใส่ schema และ seed 
    pnpm db:reset

    รัน migration ใน supabase/migrations/ ทั้งหมด แล้วรัน seed.sql (ใส่ @example.test ลง allowlist)

  3. รัน web และ API พร้อมกัน 
    pnpm dev            # ทั้งคู่
pnpm dev:web        # เฉพาะ web  → http://localhost:5173
pnpm dev:api        # เฉพาะ API  → http://localhost:3000
  4. เช็กว่าขึ้นแล้ว 
    curl -s http://localhost:3000/health      # {"status":"ok"}
curl -s http://localhost:3000/ready       # {"status":"ready"} (503 reason "db" ถ้าต่อ DB ไม่ได้)
open http://localhost:3000/openapi.json   # spec ของ API

ไม่มีฐานข้อมูลก็รัน API ได้ แต่ /ready จะตอบ 503 และ route ที่แตะ DB จะตอบ 503 db_unavailable

5. โหมด auth: mock กับ supabase

mocksupabase
ตั้งที่AUTH_MODE=mock (API) และ VITE_AUTH_MODE=mock (web)AUTH_MODE=supabase และ VITE_AUTH_MODE=supabase
การ sign-inไม่มี ทุก request เป็น mock user คนเดียว (MOCK_USER_ID)sign-up ด้วย email + password ยืนยันทางอีเมล
เหมาะกับพัฒนา UI เร็ว ๆลองระบบจริง และ E2E
ต้องมี Supabaseต้องมีฐานข้อมูล แต่ไม่ต้องมี Authต้องรัน local stack

ให้ตั้งทั้ง API และ web เป็นโหมดเดียวกัน ถ้า web เป็น mock (ไม่ส่ง token) แต่ API เป็น supabase ทุก request จะได้ 401 ส่วน web เป็น supabase กับ API เป็น mock จะทำงานได้ แต่ API ไม่ตรวจ token และใช้ mock user เสมอ

ถ้าไม่ตั้ง VITE_AUTH_MODE เลย web จะใช้ supabase เป็นค่าเริ่มต้น

6. คำสั่งที่ใช้บ่อย

รันจาก root ของ repo (แต่ละคำสั่งวิ่งทั้ง workspace)

คำสั่งทำอะไร
pnpm devweb (5173) และ API (3000)
pnpm lintoxlint
pnpm typechecktsc ทุก package และ e2e/
pnpm testVitest ของ domain, api, web (รันครั้งเดียว) API test ต้องเปิด Supabase local อยู่
pnpm buildbuild web (tsc -b && vite build) และ compile API ไปที่ dist/ (tsc -p tsconfig.build.json)
pnpm db:start / db:stop / db:resetเปิด / ปิด / รีเซ็ต Supabase local
pnpm test:supabaseตรวจ setting ของ Auth ที่ระดับ script (ต้องเปิด stack อยู่)
pnpm test:e2ePlaywright (Chromium) รัน db:start ให้ก่อน

รัน test เดียว:

pnpm --filter @investhesis/api exec vitest run src/modules/me/me.routes.test.ts
cd apps/web && pnpm vitest run src/routers/router.test.tsx -t "not found"
pnpm test:e2e auth-sign-in      # ระบุชื่อไฟล์ spec

7. รัน test ทั้งชุด (gate)

ก่อนส่งงาน ให้รันตามลำดับนี้จาก root และหยุดที่ขั้นแรกที่ fail

pnpm db:start && pnpm db:reset
pnpm test:supabase
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm test:e2e

พอร์ต 5173 ถูกใช้อยู่? E2E ใช้พอร์ต 5173 และ 3000 ถ้าโปรเจกต์อื่นใช้ 5173 อยู่ ให้รัน E2E_WEB_PORT=5174 pnpm test:e2e (ไม่ต้องปิดโปรเจกต์อื่น)

ผล E2E อยู่ที่ e2e/.output/html ชื่อ test ทุกตัวขึ้นต้นด้วยรหัส TC- ของ test case
