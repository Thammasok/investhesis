# Web app (`apps/web`)

In `apps/web`: `pnpm dev` (port 5173, proxies `/api` → `http://localhost:8080` and strips the `/api` prefix, since the API serves `/auth/*` and `/me` bare; `PACTA_API_ORIGIN` overrides the target, and `vite preview` uses the same proxy; `pnpm dev` answers only `/api/exports*` from an in-memory mock (the exports slice has no API yet; `mocks/dev-mock-paths.ts` `mockedInDev(path, env)` decides, TC-U-086), while folders, uploads, documents (list, stats, review, save, confirm, region re-read) and templates go through the proxy to the real API, which reads uploads with the mock OCR provider (`OCR_PROVIDER=mock`, the default outside production) and needs `pnpm stack:up` and `STORAGE_DRIVER=gcs` in `apps/api/.env`; with `PACTA_MOCK_FILES=true` in `apps/web/.env` it answers `/api/folders*`, `/api/documents*`, `/api/uploads*`, `/api/templates*` and `/api/exports*` from the whole in-memory mock (`DocumentsBackend` over `FilesBackend`) seeded with a sample Thai folder tree, OCR results and the design's sample invoice (mocked Vitest and E2E runs never use this plugin; uploads are read about 6 s after they arrive, a name containing `password` or `locked` fails as password-protected, and a seeded document's page is drawn as SVG with a box per value; dev server only), while sign-in and `/me` still need the real API; it also answers `PATCH /api/me` (`mocks/vite-mock-account.ts`, on by default, `PACTA_MOCK_ACCOUNT=false` turns it off): it reads the real `GET /me` with the same token, keeps a saved display name in memory per user and lays it over later `GET /api/me` answers until restart, while `POST /api/auth/change-password` goes through to the real API (a real change, with the notice email in Mailpit); and `/api/billing/*` from one in-memory workspace (`mocks/vite-mock-billing.ts`, placeholder packages, a test card, sample history; anyone may change billing there; `PACTA_MOCK_BILLING=false` turns it off)), `pnpm build`, `pnpm preview`, `pnpm lint` (oxlint), `pnpm typecheck` (`tsc -b`), `pnpm format` / `pnpm format:check` (Prettier + Tailwind class sorting), `pnpm test` / `pnpm test:watch`. Single test: `pnpm vitest run src/routers/router.test.tsx -t "not-found"`.

## Conventions

Stack: Vite 8, React 19, TypeScript 7 (strict, `noUncheckedIndexedAccess`), Tailwind v4, shadcn/ui, React Router v8 (data mode), TanStack Query v5, TanStack Table v9 (`@tanstack/react-table`, data tables only), dnd-kit (`@dnd-kit/core` 6, `sortable`, `modifiers`, `utilities`; the stable packages, not the pre-1.0 `@dnd-kit/react`; drag-and-drop ordering only), Zustand, i18next, Zod, Vitest + Testing Library.

- **Lint is oxlint, not ESLint:** `typescript-eslint` doesn't support TypeScript 7. Config is in `.oxlintrc.json`.
- **Layout:** `@/` aliases `src/`. All file and folder names are kebab-case. Domain code goes in feature folders under `src/features/<feature>/` (api, query hooks, components). Features don't import from each other; shared code goes in `lib/` or `components/`.
- **Routing:** the route table is in `src/routers/router.tsx` (`createBrowserRouter`). Page components (views) live in `src/views/`; each exports `Component` and loads via `lazy`, so each page is its own chunk. Keep routing config in `routers/` and page UI in `views/`. Import from `react-router`, and `RouterProvider` from `react-router/dom` (`react-router-dom` no longer exists in v8). `/` is the public landing page (`views/landing.tsx`, copy in the `landing` i18n namespace) under `PublicLayout`, which also serves public 404s. The public route (id `PUBLIC_ROUTE_ID`) has the loader `loadSessionStatus` (`routers/guards.ts`), which never redirects or throws (a failed check reads as signed out); `PublicLayout` and the landing page read it with `useSessionStatus()`, and a signed-in visitor sees a dashboard link to `/main` (`nav.dashboard` in the header, `landing:dashboardCta` in the hero) instead of sign-in, "Get started" and "Create a free account". The signed-in area is a pathless route (id `app`, loader `requireAuth`, `AppLayout`) with three roots: `/main` (home and most pages), `/files` (File management) and `/account` (account settings). `AppLayout` (`components/layout/`) is its shell, built from shadcn's `sidebar-08` block (inset sidebar; header with trigger and breadcrumb). Language and theme live in the sidebar's account menu as submenus, reusing `LanguageRadioGroup` / `ThemeRadioGroup` from the header switchers that the public and auth layouts still use; add app pages as children of `/main` unless they get their own root (then add it to `APP_ROOTS` in `features/auth/redirect-to.ts`). Sidebar pieces live in `components/layout/sidebar/`; on a phone a nav link closes the sidebar sheet when tapped. The signed-in user's storage gauge (`StorageGauge` in `nav-storage.tsx`; `storage` keys in `common`; red at 90 % or more; skeleton while `/me` loads) always shows under the user summary in the account menu, and below the Settings group only once usage reaches 90 % (`NavStorage`, `STORAGE_NEARLY_FULL_PERCENT`; hidden in icon mode); in the menu it sits outside the menu items (not a menu item, so arrow keys skip it). The usage is a mock until the API reports it: `features/account/storage-usage.ts` gives every user a 10 GB quota (`STORAGE_QUOTA_BYTES`) and a stable used share (5–95 %) picked from the user id (`mockStorageUsage`); swap `useStorageUsage` for a query when the endpoint exists. Nav items are in `nav-items.ts`: an item without `to` renders as a disabled "coming soon" entry, so give it `to` when its page lands. A route's `handle: { crumb: '<common key>' } satisfies RouteHandle` sets its breadcrumb label. After a successful sign-in or sign-up verification, the views navigate to `/main` with `replace`. Guards live in `routers/guards.ts`: `requireAuth` (loader on the signed-in area) sends a signed-out visitor to `/auth/sign-in?redirectTo=<path+search>`, and `redirectIfSignedIn` (sign-in, sign-up; forgot-password stays open) sends a signed-in one to `safeRedirectTo(redirectTo) ?? '/main'`. Both use `authClient.getSession()` and make no network call while the in-memory session is valid. `features/auth/redirect-to.ts` `safeRedirectTo` accepts only same-origin paths in the signed-in area (`isAppPath`: `/main`, `/files`, `/account` and below). `features/auth/auth-listener.ts` `listenForSignOut({ router, queryClient })` is called once in `app.tsx`: on sign-out (this tab, or another tab via the AuthClient's `BroadcastChannel` relay) it clears the Query cache and replaces to sign-in; for `session_invalid` it also keeps `redirectTo` and shows the `common:session.ended` toast. The user menu shows the signed-in user from `useMe()` (`features/account/api/me.ts`, `GET /me`, key `['me']`; skeleton while loading); its "Account" item links to `/account` and "Preferences" (`accountSections.preferences`) to `/account/preferences` (both close the sheet on a phone; the menu has no "Settings" item, while the sidebar's disabled "Settings" entry stays), and its "Sign out" item calls `authClient.signOut({ reason: 'user' })`; the sign-out listener clears the Query cache and navigates. Tests render the real `routes` with `renderRoute(path, { authClient })` from `src/test/render.tsx` (memory router + fresh QueryClient, sign-out listener wired; `authClient` is a `FakeAuthClient`, signed out by default). `/main` tests pass `await signedInClient()`.
- **Auth pages:** `/auth/sign-in`, `/auth/sign-up` and `/auth/forgot-password` render under the `/auth` route, which uses `AuthLayout`; `/auth` alone redirects to sign-in. `AuthLayout` is `components/layout/auth-layout.tsx` (the two-column layout from shadcn's `login-02`/`signup-02` blocks). The forms live in `features/auth/components/`. The GitHub buttons were removed. Sign-in links to `/auth/forgot-password`. Copy is in the `auth` i18n namespace. Forms call `AuthClient` (from `@/integrations`) through `useAuthForm` (`features/auth/use-auth-form.ts`): it always calls `preventDefault` (so the native GET can't put the password in the URL), validates with `noValidate` plus our own checks (`form-issues.ts`), ignores a second submit while one is pending, and moves focus to the first field with an issue. Errors are kept as data (`Issue`) and translated at render by `useIssueText`, so a language switch updates them; each `AuthErrorCode` has a key under `errors` in the `auth` namespace. A field error is a `role="alert"` message linked by `aria-invalid` and `aria-describedby` (`FieldIssue`, `issue-props.ts`). Sign-in goes to `safeRedirectTo(redirectTo)` or `/main` (replace); an `email_not_verified` error shows the code step in place with the returned ref. The reset flow's last step has a "start over" button for `invalid_reset_token`. Don't destructure refs out of `useAuthForm` into JSX as `form.attachForm` and read `form.errors` on the same object: oxlint's `react(refs)` flags it, so destructure the result.
- **Multi-step auth pages (sign-up, forgot password):** each step is a form in `features/auth/components/`, and the view holds the current step. Sign-up: details, then email code. Forgot password: email, then code, then new password (Pacta-owned code-based recovery through the API: `POST /auth/forgot-password`, `/auth/verify-recovery`, `/auth/reset-password`), then a toast on sign-in. The code step is the shared `OtpForm` (6-digit code via shadcn `input-otp`, resend cooldown 60 s, a Pacta API setting). The step is local state, not a route, so the email never reaches the URL; the details form is hidden, not unmounted, so "use a different email" keeps what was typed. `OtpForm` shows the API's ref code (`CodeSent.refCode`, new on every send) so users can match the code to the email, runs the resend cooldown from `CodeSent.resendAvailableAt`, and resends through `authClient.resendCode` (a `rate_limited` error shows a toast with the wait and leaves the cooldown alone). A wrong code is an inline error on the code field that clears and refocuses it. `NewPasswordField` (rules tooltip, strength meter, blocks weak passwords; takes translated `error` text) is shared by sign-up, reset and the account page's change password. It lives with `PasswordInput`, `PasswordStrength` and `password-rules.ts` in `components/password/`, with their copy in the `password` group of `common`; the code step's copy is the `otp` group of the `auth` namespace. A resend shows a Sonner toast, so `renderRoute` mounts `<Toaster />` like `app.tsx`. `test/setup.ts` stubs `document.elementFromPoint` (input-otp), `window.matchMedia` (Sonner), and `hasPointerCapture` / `releasePointerCapture` / `scrollIntoView` (Radix Select), which jsdom lacks. In tests a Radix `Select` is a `combobox`: click it, then click the `option` in the `listbox` (`selectOptions` only works on a native `<select>`).
- **UI:** build from shadcn primitives in `src/components/ui/` (radix base, nova preset, `components.json`). Don't add other UI libraries. Theme tokens are CSS variables in `src/index.css`. Fonts: Geist, with Noto Sans Thai as the fallback for Thai glyphs. `sonner.tsx` was changed to read the theme from the Zustand store instead of `next-themes`, so re-apply that change if you ever overwrite it. Likewise `sidebar.tsx` takes a `sheetTitle` prop (translated mobile sheet title, replacing the hard-coded English title and description), and `hooks/use-mobile.ts` was rewritten with `useSyncExternalStore` to satisfy oxlint. When adding blocks, answer "no" to overwriting existing `ui/` files.
- **State:** server data goes in TanStack Query only (`lib/query-client.ts`; tests use `createQueryClient()` for a fresh client). Zustand (`src/stores/`) is for client state only, such as theme and locale, and never holds API data.
  - `theme-store`: `light | dark | system`, persisted as `pacta-theme`. An inline script in `index.html` reads the same key to set `.dark` before first paint, so keep the two in sync.
  - `locale-store`: persisted as `pacta-locale`.
  - `files-layout-store`: `list | grid` for File management, persisted as `pacta-files-layout`.
- **Auth client (`src/integrations/auth/`):** app code reaches auth only through the `AuthClient` port, via `authClient` from `@/integrations` (swap it in tests with `setAuthClient`) and the port types from `@/integrations/auth/auth-client`. An oxlint `no-restricted-imports` rule rejects imports of adapters such as `pacta-auth-client.ts` (allowed only inside `src/integrations/` and `src/test/`). `PactaAuthClient` keeps the access token in private memory only (never `localStorage`, Zustand or the Query cache), refreshes single-flight inside the `pacta-auth-refresh` Web Lock, and broadcasts sign-out on `BroadcastChannel('pacta-auth')`. `FakeAuthClient` and the MSW-backed `PactaAuthClient` tests both run `describeAuthClientContract`, and `FakeAuthBackend` is the shared in-memory rules. msw is a dev dependency.
- **File management (`/files/:folderId?`; old `/main/files/...` links redirect there keeping the query; `views/files.tsx`, `features/files/`; labelled "File management" / "จัดการไฟล์", code names stay `files`):** one route with an optional segment, so moving between folders keeps the page and its upload queue mounted. The sidebar item (`nav.files`) has `matchNested`, so it stays active inside folders. Search, sort and page all live in the URL (`?q=inv&sort=name&page=3&size=48`; `listing.ts` `readListing` / `listingSearch` leave defaults out), so reloads, links and Back/Forward keep them, and a folder link starts clean. A new search, sort or page size goes back to page 1; typing in the search replaces the history entry instead of adding one. Search (`SearchBox`, a wrapper over the shared `components/search-box/` box: debounced 300 ms, Esc or X clears, follows outside changes to `q`) matches folder and file names in the open folder only, case-insensitively, and has its own no-matches state. Sort (`SortSelect`, plus clickable Name / Size / Uploaded headers with `aria-sort` in the list view; `FilesTable` is a `DataTable` whose column ids are the API sort keys, mapped by `sortToColumnSort` / `columnSortToSort` in `listing.ts`, and `FilesTableSkeleton` is the same columns with `loadingRows`) is `-createdAt` (default) | `createdAt` | `name` | `-name` | `-size` | `size`; folders follow it, falling back to name for a size sort (`folderSortFor`), and names use Thai collation on the server. Files are paged on the server (`GET /documents?folderId=&q=&sort=&page=&pageSize=` returns `{ items, page, pageSize, total }`); folders (`GET /folders?parentId=&q=&sort=`) aren't paged and show on page 1 only. Sizes are 24 / 48 / 96, which fit the grid's 2, 3, 4 and 6 columns. the shared `DataPagination` (see Data tables) shows the range, a native size select and page links; it shows whenever the folder (or the current search) has files, and the page links only when there's more than one page. `useDocuments` and `useFolders` keep the previous result on screen while a new page, search or sort loads (only within the same folder), and a page past the end is replaced with the last page. `ui/pagination.tsx` lost `PaginationLink` / `Previous` / `Next` (plain `<a>`, English labels); page links are `Button asChild` + `Link`. A List / Grid switch (`LayoutToggle`, a radio group) shows `FilesTable` or `FilesGrid` (cards, folders first; a folder card's link stretches over the card); the choice is per browser in `stores/files-layout-store.ts` (persisted as `pacta-files-layout`, reset to `list` in `test/setup.ts`). Each row or card has a "⋯" menu (`ItemActions`, shared with `StatusBadge` by both layouts) (`DropdownMenu modal={false}`, so a dialog opened from it can't leave `pointer-events: none` on `<body>`) with Rename, Move and Delete; the view holds which row's dialog is open (`RenameDialog`, `MoveDialog`, `DeleteDialog`). A file rename edits only the base name (`checkFileRename` in `names.ts` keeps the extension). Move browses the folder tree from the item's folder and leaves the moved folder out, so it can't go inside itself. Delete confirms, and a non-empty folder can't be deleted. The mutations (`useRenameItem`, `useMoveItem`, `useDeleteItem`) refresh everything under `['files']`, and `manage-issue.ts` maps their errors to message keys. The API side isn't built yet: `features/files/api/schemas.ts` is the expected contract (`GET /folders?parentId=`, `GET /folders/:id` with `path`, `POST /folders` (409 `folder_name_taken`), `PATCH /folders/:id` (`name`, `parentId`; 409 `folder_name_taken`, 400 `folder_cycle`), `DELETE /folders/:id` (409 `folder_not_empty`), `GET /documents?folderId=&page=&pageSize=` (paged), `POST /uploads` (413 `payload_too_large`, 415 `unsupported_file_type`, 404 `folder_not_found`) then `POST /documents { uploadId }`, `PATCH /documents/:id` (`originalFilename` with the same extension, `folderId`), `DELETE /documents/:id`), and `apps/web/mocks/files-backend.ts` (`FilesBackend`, plain Fetch `Request`/`Response`, never in the bundle) serves it to Vitest through MSW, to the mocked Playwright run, and to `pnpm dev` through `mocks/vite-mock-files.ts`. Allowed uploads are `FILE_UPLOAD_RULES` in `lib/file-types.ts` (shared, with `kindOfMime`, `isExtractable`, `checkFile` and `fileIssue`): `.pdf .jpg .jpeg .png .webp .doc .docx .xls .xlsx`, up to 20 MB each, at most 20 files per pick or drop (`checkFile` runs the shared `checkAgainstRules` and adds the kind; it imports `components/file-upload/validate-files.ts` by relative path with `.ts` because the dev and E2E mocks import it outside Vite's aliases). The extension decides the kind, and a specific MIME type must agree with it, while an empty or generic one is left for the API to sniff. Only PDFs and images are extractable; Word and Excel show a "stored only" badge instead of an OCR status. Names: `names.ts`, with folder names (trimmed, 1–100 characters, no `/`, `\` or control characters, unique per parent case-insensitively on the API). The Upload button opens `UploadDialog` (`features/files/components/upload-dialog.tsx`: the shared `FileUploadDialog` with `FILE_UPLOAD_RULES`, listing the queue as `UploadAttachmentList` items); a drop anywhere on the folder (`FileDropzone`) is checked with the same rules, saves into that folder and opens the dialog too. The dialog's "Save to" row (the `destination` slot: full path from the root, a Change button) starts as the open folder each time Upload is pressed; Change swaps the body for a choose-folder `step` (`FolderBrowser`, Back, Save here; focus moves to the step heading and back to Change), and the view keeps the chosen `destinationId` until the next Upload. Files go to their own folder without navigating; each queue item keeps its `folderId`, so the right listing is refreshed. `FolderBrowser` ("Up to …" as the list's first row, the folders inside, open on click; `excludeId` leaves one out; the list is at least `min-h-48`) is shared with `MoveDialog`, with copy under `folderBrowser`. In the upload picker it also has a "New folder" row (only when `onCreatingChange` is passed; `MoveDialog` doesn't) that becomes an inline name field (`NewFolderForm`: `checkFolderName` before any request, server errors inline, the same `createFolder.*` copy as `CreateFolderDialog`); a created folder opens and focus goes to Save here. The caller holds `creating`, because Radix handles Escape in the capture phase: `UploadDialog` passes the shared dialog's `onEscapeKeyDown` so Escape closes the name field first, then the picker (focus back on Change), and only then the dialog. The dialog stays open to show progress (its button reads Done once anything is listed); closing it doesn't stop uploads, and an "Uploads (done/count)" button next to Upload reopens it. Uploads go through `UploadQueue` (`lib/upload-queue.ts`, shared; an external store for `useSyncExternalStore`, 3 at a time, with cancel, retry for request failures, dismiss and clear-finished; the caller passes the file `check` (File management uses `fileIssue`); `add(files, folderId, rejected, fields)`, where `fields` are extra finalize-body fields sent with each file, also lists files the dialog turned away; each item keeps its `File` for image thumbnails) via `useUploadQueue`. A finished upload invalidates that folder's documents query. Leaving for another signed-in page (`isAppPath`) while uploads run asks first (`useBlocker`, `LeaveUploadsDialog`); sign-out isn't blocked and unmounting aborts what's running. Copy is in the `files` i18n namespace.
- **Documents (OCR) (`/documents`, `/documents/:id`, `/review`, `/exports`; all in `APP_ROOTS`; `views/documents.tsx`, `views/document-review.tsx`, `views/review-queue.tsx`, `views/exports.tsx`, `features/documents/`; copy in the `documents` namespace; built from `.claude/design/Pacta — Document Extraction UI.html`: Phase 1 parts plus Templates & fields (below); API keys and Embed & webhooks are "coming soon" nav entries, and the export page lists REST API, webhook, embed and SAP/ERP as later destinations):** the contract is `features/documents/api/schemas.ts` (CONCEPT's header + line items, every value `{ value, confidence, source, box }`, money and quantities as decimal strings; `GET /documents?scope=all&view=&q=&type=&sort=&page=&pageSize=` with per-view `counts`, `GET /documents/stats`, `GET /documents/:id`, `GET /documents/:id/file` (signed URL plus `contentType`), `PATCH /documents/:id/extraction`, `POST /documents/:id/confirm | reprocess`, `POST /documents/read` (`useReadDocuments`; per-document `queued | not_readable_type | already_processing | document_confirmed | document_not_found`, 429 `ocr_quota_exceeded`), `POST /documents/:id/region-reads` (`useRegionRead`; `RegionReadAnswer`, 400 `region_too_small`, 409 `document_not_editable`, 429 with Retry-After, 502 `ocr_unavailable`), `GET /documents/:id/file?page=n` (`useDocumentFile(id, enabled, page?)`), `extraction.custom` (template custom fields, `removed` ones read-only), `ExtractionUpdate.custom` and `regionReads`, `low` and `source: 'region'` on every value, `queued` on every summary (polling only while a read is open: `shouldPoll` / `isReading` in `polling.ts`; "not read yet" is `uploaded` with `queued` false), failure code `too_many_pages`, `GET|PUT /exports/settings`, `POST /exports { documentIds? }` answering the file; upload is File management's signed `POST /uploads` → PUT → `POST /documents { uploadId }`, with optional `typeHint` and `ocrLanguage` in the finalize body, which the API ignores for now) and `apps/web/mocks/documents-backend.ts` (`DocumentsBackend`, samples and the SVG drawing in `documents-samples.ts`; exports are always CSV with a BOM in the mock) serves it to Vitest, `pnpm dev` and the mocked E2E run. Views (tabs) are `all | needs_review | processing (uploaded or processing) | confirmed ("Approved", not exported) | exported | failed`. The list (`DocumentsTable`, a `DataTable` whose checkbox cells and retry button read a selection context so the columns stay stable) keeps view, search, type and page in the URL (`listing.ts`), polls every 2 s while anything on the page is being read, and resets the selection when the listing changes; "Export selected" works only when every selected document is confirmed. Upload opens `UploadDialog` (`features/documents/components/upload-dialog.tsx`: the shared `FileUploadDialog` with `OCR_UPLOAD_RULES`, the batch settings (type hint, OCR language) in its `destination` slot, the queue as `UploadAttachmentList`; it stays open to show progress and an "Uploads (done/count)" button reopens it). Files go through the shared `UploadQueue` with `ocrFileIssue` (PDF and images from `lib/file-types.ts`; Word and Excel are turned away) to the workspace root through the same `uploadDocument` as File management (phases, "Checking…" and the same error codes), with the settings as finalize fields (`use-document-uploads.ts`); leaving while uploads run asks first. The review screen holds a `Draft` (`review-draft.ts`: strings in inputs, `toUpdate` cleans them; `isDirty` compares after cleaning) and runs `runChecks` (`checks.ts`: subtotal + VAT = total, line sum = subtotal, VAT at the rate ±0.01, qty × price − discount = amount per line, 13-digit Thai tax ID checksum; `suggestTaxId` swaps look-alike letters) on every edit; exact arithmetic is `lib/decimal.ts` (BigInt units). A field is tinted only when the API says it is `low` (`isLow` in `confidence.ts`; there is no fixed threshold); a page box or a failing check's "go to the field" switches tab and focuses the input (`fieldDomId`, `flushSync`). Approve asks first when checks fail, saves unsaved edits, then confirms; Approve & next opens `fetchNextToReview` (oldest needs_review) or returns to the list. `/review` redirects to the oldest waiting document. Downloads go through `lib/save-file.ts` and copies through `lib/clipboard.ts` (mock both in tests); `apiDownload` in `lib/api-fetch.ts` returns `{ blob, filename }` from Content-Disposition. `ConfirmDialog` (`components/confirm-dialog.tsx`) is the shared yes/no alert dialog. The review draft (`review-draft.ts`) also holds custom values (`customPath`, `setCustom`) and applied region reads (`applyRegionRead`, `discardRegionRead`; `toUpdate` sends a region read id only while the field still holds its value). The checks have a shared case table, `features/documents/cases/checks.cases.json`, run by `checks.cases.test.ts` (and by the API against its copy); add rows there, never compute `expected` at run time. The mock gained `readQuota`, `regionText`, `failNextRegionRead`, `addDocument(..., { queued: false })` for "not read yet", and `templates.role = 'member'` for the 403 case; the default template is the 16 locked standard fields plus the type's custom ones (tests: `mocks/documents-contract.test.ts`, TC-U-070). Tests: `views/documents.test.tsx` (TC-U-620…625), `views/document-review.test.tsx` (TC-U-630…638), `views/exports.test.tsx` (TC-U-640…642), `features/documents/*.test.ts` (TC-U-603…607, 626, 627), `lib/decimal.test.ts` (TC-U-600…602), `mocks/documents-backend.test.ts` (TC-U-610…614; its upload goes intent, PUT, finalize).
- **Review viewer, custom fields and read states (`views/document-review.tsx`, `features/documents/`):** `DocumentViewer` shows one page image at a time from `useDocumentFile(id, true, page)` for every document (no `<object>` PDF viewer any more); it takes `pageCount` and `boxes` (each `ViewerBox.box.page` counts from 1), keeps its own page, and moves to a field's page when `active` changes to a path that has a box (a path with none leaves the page alone). The footer (`output` "Page n of m", previous and next) is absent for one page; PageUp and PageDown turn pages from anywhere inside the viewer; the scrollable page region is focusable. Pure helpers are in `viewer-pages.ts` (`boxesOnPage`, `pageOf`, `nextPage`, `prevPage`) and `failures.ts` (`canRetry`: not for `password_protected` or `too_many_pages`). Boxes never rely on colour alone: an unsure box is dashed and described by "Low confidence" (`aria-describedby`), the selected one has a ring and `aria-current`. Custom fields are one `fieldset` after the header sections (`components/custom-fields.tsx`, absent when there are none), each a `ReviewField`; a `list` field is a select whose options come from `useTemplate(type, enabled)` (only asked when a list field exists), a `removed` one is read-only with a badge but still focusable and copyable, and a value with `source: 'region'` shows the region badge until it is edited; custom values are in the JSON tab under `custom`, keyed by output key.
