# Local stack, database and guards

Local stack (Docker, `docker-compose.yml`, all bound to 127.0.0.1): `pnpm stack:up` (postgres 18 on 5432, postgres-test on 5433 db `pacta_test`, Mailpit SMTP 1025 and UI http://127.0.0.1:8025, `gcs` = fake-gcs-server 1.56.1 on 4443 with a `gcsdata` volume; waits until healthy, then `docker compose run --rm gcs-init` (profile `tools`, idempotent: a 409 counts as success) creates the buckets `pacta-dev` and `pacta-test`; the image is alpine-based so the busybox `wget` healthcheck works; CORS comes from `-cors-headers=Content-Type,x-goog-content-length-range`; the emulator does not enforce `x-goog-content-length-range` or `ifGenerationMatch`), `pnpm stack:down`, `pnpm db:update` / `pnpm db:update:test` (one-off Liquibase containers, contexts `dev` / `test`, changelog in `db/changelog/master.yaml`). Changesets are formatted SQL in `db/changelog/changes/` (0001 schema, 0002 identity, 0003 auth, 0004 rate limits, 0005 dev seed, context `dev`; 0006 idempotency keys; 0007 revoke reason; 0008/0009 user avatar; 0010 avatar parts only (converts seed avatars with an md5-per-part hash, tightens `users_avatar_shape_chk` to `kind = 'parts'`; its rollback only loosens the check); 0011/0012 user preferences; 0013 audit log; 0014 files: folders, documents, upload intents, storage deletions, with tenant-safe composite folder FKs; 0015 `upload_intents.cleanup_queued_at` (set once by the storage cleanup task); 0016 `app.jobs` (one open job per `dedupe_key` through the partial unique index `jobs_open_dedupe`); 0017 OCR columns on `app.documents` plus `documents_tenant_id UNIQUE (tenant_id, id)` and `app.document_pages` (page images at `tenants/{t}/document-pages/{d}/{n}.jpg`); 0018 `ocr_runs`, `document_headers`, `document_line_items`, `region_reads`, `field_corrections` (tenant-safe composite FKs to documents); 0019 `extraction_templates` and `template_fields` (a `table` field must have `standard_key = 'lineItems'`, NULL-safe); 0020 `ocr_usage`; 0021 widens the `audit_log.entity_type` CHECK to `template`; 0022 dev seed of six read documents, context `dev`; each changeset has a rollback, tested with `rollback-count` on a scratch database (never on the shared `pacta_test`); dev password `Dev-Passw0rd!`). Liquibase's tracking tables live in `app`; a `db-init` container creates the schema first, because Liquibase cannot create its own tracking schema. `pnpm test:db` applies the test changelog, then runs `db/tests/schema.test.sh` (psql in postgres-test; also checks the dev seed when the dev DB is migrated). Override host ports with `PACTA_PG_PORT`, `PACTA_PG_TEST_PORT`, `PACTA_SMTP_PORT`, `PACTA_MAILPIT_UI_PORT`, `PACTA_GCS_PORT` (change `GCS_API_ENDPOINT` / `GCS_PUBLIC_ENDPOINT` to match) when another stack holds them. Liquibase is pinned to `4.33.0-alpine` because it bundles the PostgreSQL JDBC driver (5.x images do not). Postgres 18 mounts `/var/lib/postgresql`, not `.../data`. Config templates: `apps/api/.env.example` (API), `apps/web/.env.example` (only `PACTA_API_ORIGIN`, the dev/preview proxy target, read by `vite.config.ts` through `loadEnv`), and the root `.env.example` (Docker Compose host-port overrides only); `node scripts/gen-dev-keys.mjs` prints `JWT_PRIVATE_KEY`, `OTP_PEPPER`, `GCS_CLIENT_EMAIL` and a throwaway RSA `GCS_PRIVATE_KEY`, `node scripts/hash-password.mjs [pw]` prints an argon2id hash. Guards: `pnpm test:scripts` (node --test, with failing fixtures per guard), `pnpm check:process-env` (`process.env` only in `apps/api/src/config/env.ts`), `pnpm check:integrations` (vendor imports only in their adapter, see `scripts/integration-boundary.txt`; a path ending in `/` allows a whole folder, e.g. `@google-cloud/storage` only under `apps/api/src/integrations/storage/`, SDK pin 8.4.0 when added), `pnpm check:secrets` (run after a web build: server secret names and PEM private key blocks must not appear in `apps/web/dist`), `pnpm check:layers` (API layer rules, see "API layers"), and `pnpm guard` (process-env, integrations and layers together; `pnpm --filter @pacta/api lint` also runs process-env and layers). API data layer (`apps/api/src/db/`): Drizzle is typing and queries only (`schema/*.ts`, `pgSchema('app')`, hand-written; no drizzle-kit anywhere), `createDb(config)` in `client.ts` returns `{ db, pool, ping, close }` and `main.ts` passes it to `buildApp`, so `/ready` pings the pool and `onClose` ends it. `pnpm test:api` migrates `pacta_test` (`db:update:test`) then runs the api tests, including `schema-drift.test.ts` (ADR-006: Drizzle columns vs `information_schema` in both directions; fails naming `table.column`; add every new table or column to `schema/` in the same change as its changeset; `test/introspect.ts` reports `numeric(p, s)` so a wrong precision is drift too). Each test file gets its own database cloned from the `pacta_test` template via `test/test-db.ts` (`createTestDb()`, dropped in `afterAll`) or `test/build-test-app.ts` (`buildTestApp()`); api tests need the compose test DB up. Set `TEST_DATABASE_URL` (the template URL) or `PACTA_PG_TEST_PORT` when 5433 is taken. Mailer (`apps/api/src/integrations/mailer/`): the SMTP and contract tests need compose Mailpit; when host ports are overridden run them with `SMTP_URL=smtp://127.0.0.1:<PACTA_SMTP_PORT> MAILPIT_API_URL=http://127.0.0.1:<PACTA_MAILPIT_UI_PORT> pnpm --filter @pacta/api test` (defaults 1025/8025; the tests clear that Mailpit inbox). `pnpm --filter @pacta/api test:mailtrap-sandbox` sends one real message and skips unless `MAILTRAP_TOKEN` and `MAILTRAP_TEST_INBOX_ID` are set.

OCR (ocr-extraction v1.0): no compose service is added. The local stack runs reads with `OCR_PROVIDER=mock` (the `.env.example` default); the OCR and job variables are listed in `apps/api/.env.example`, and operating a real provider (variables, daily cap, worker switches, PDPA checklist, enabling after a passing eval) is in `ops/ocr/README.md`. A local model is optional: `docs/guides/local-llm.md`.
