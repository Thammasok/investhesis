# Testing

E2E (Playwright, `apps/web/e2e/`; first run on a machine: `pnpm --filter @pacta/web exec playwright install chromium`; versions are pinned): `pnpm test:e2e` (root) is mocked mode: it builds the production bundle into `dist-e2e-mocked`, serves it with `vite preview`, and answers every `/api` request from `e2e/mocks/mock-api.ts` through `page.route` (an unmocked request fails the test); projects `chromium` and `mobile`. `pnpm test:e2e:integration` (root) is integration mode and needs only Docker: `e2e/integration/run.mjs` starts a throwaway compose project `pacta-e2e` (Postgres, Mailpit and fake-gcs-server, whose buckets `gcs-init` creates), runs `pnpm db:update`, makes dev keys (JWT, OTP pepper, GCS signing key) with `scripts/gen-dev-keys.mjs`, builds the bundle, runs Playwright (which starts three APIs from source with `MAIL_PROVIDER=smtp`, `STORAGE_DRIVER=gcs` on bucket `pacta-test` plus a `vite preview` per API; the ttl and rotate profiles exist for TC-E-016 and TC-E-020), then removes the stack and its volume (`PACTA_E2E_KEEP_STACK=1` keeps it). The HTML report is `apps/web/playwright-report/integration` (`.../mocked` for mocked). Host ports follow the compose overrides `PACTA_PG_PORT`, `PACTA_SMTP_PORT`, `PACTA_MAILPIT_UI_PORT`, `PACTA_GCS_PORT`; API and web ports start at `PACTA_E2E_API_PORT` (8787) and `PACTA_E2E_WEB_PORT` (4174). Specs read codes from Mailpit in integration mode and use `e2e+<worker>-<uuidv7>@pacta.local`; test titles start with their TC id; results are in `docs/features/user-auth/v2.0/test-report-t016.md`. `MockApi.documents` is a `DocumentsBackend` (`apps/web/mocks/documents-backend.ts`) that answers `/api/folders*`, `/api/documents*` and `/api/exports*`, and `MockApi.files` is its `FilesBackend` (`apps/web/mocks/files-backend.ts`); uploads stay unread until a spec calls `documents.finishProcessing(id, spec?)`; `e2e/documents.spec.ts` (TC-E-110 upload → review → approve → export download, TC-E-111 no sideways scroll and no serious axe findings on the list, a review page, the export page and the templates page, TC-E-112 drag-and-drop ordering of template fields (keyboard) and export columns (mouse), scanning the page content but not the sidebar or the shared pagination, whose known issues are noted in the spec) also runs in mocked mode only; `e2e/files.spec.ts` (TC-E-100 folder + upload through the upload dialog's device source, TC-E-101 drop on the folder (opens the dialog) + rejected type, TC-E-102 rename, move and delete, TC-E-103 grid layout, TC-E-104 paging, TC-E-105 search and sort) runs in mocked mode only (it is seeded through the mock tree; the integration journeys are TC-E-260…289 below). `openSidebar` waits for the shell (the account menu or the sidebar toggle) before deciding whether to open the sheet. Vitest, `tsc -b` and oxlint all skip or cover `e2e/` appropriately (`vite.config.ts` excludes `e2e/**` from Vitest). Add shadcn components with `pnpm dlx shadcn@latest add <name>`.

Real-bucket GCS test (file-storage v1.0 T-011): `pnpm test:gcs-real` runs `apps/api/src/integrations/storage/gcs-storage.real.test.ts` with its own config (`apps/api/vitest.gcs-real.config.ts`); `pnpm test` excludes `*.real.test.ts`, and the full test gate does not include it. It is skipped (exit 0, "skipped" in the output) unless `GCS_REAL_BUCKET` is set. Variables: `GCS_REAL_BUCKET` (bucket to test; enables the run), `PUBLIC_WEB_ORIGIN` (must match the bucket CORS origin; the preflight case is skipped without it), `GCS_PROJECT_ID` (optional), `GCS_CLIENT_EMAIL` + `GCS_PRIVATE_KEY` (optional signing key; without them signing is keyless through IAM and application default credentials, so run as an identity with Token Creator on the runtime service account). It proves what fake-gcs-server cannot: signature check, rejection of a wrong `Content-Type` and of a body larger or smaller than the declared length, the `ifGenerationMatch: 0` copy precondition, CORS preflight, and signed GET expiry. It writes only under `staging/real-test/` and deletes its objects. Bucket setup: `ops/gcs/README.md`; the JSON files are checked by `gcs-config.test.ts` (TC-U-076, TC-U-077).
